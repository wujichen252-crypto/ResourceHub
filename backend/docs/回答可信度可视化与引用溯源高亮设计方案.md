# 回答可信度可视化 + 引用溯源高亮 设计方案

> 版本：v1.0（2026-11-05）
> 状态：待实现
> 关联模块：AI 对话（/api/ai/chat）、笔记检索（retrieval.py）、前端 AI 消息组件（AIMessage.vue）
> 定位：把「AI 说的话可不可信、依据来自哪篇笔记哪一段」从黑盒变成可见、可点、可验证的界面能力，是比赛「可信 AI」创新点的落地文档。

---

## 1. 背景与现状差距

现有 RAG 链路已经具备**溯源的骨架**，但只走了半程：

| 已有能力 | 位置 | 缺口 |
|---|---|---|
| 模型被要求标注 `[1][2]` 来源编号 | `services/ai/safety.py` SYSTEM_GUARD 第 3 条 | 编号只是**纯文本**，不可点、不高亮，用户要自己对答案去找引用 chip |
| 检索命中带 score（RRF/向量/BM25） | `retrieval.py` `SearchHit`，`chat_service.py` citation 事件 | score 只展示为「匹配度 x%」，没有参与任何可信度判断 |
| 引用 chip 点击展开片段 | `AIMessage.vue` citations 区块 | 展开后**片段里哪一句支撑了结论**仍要用户自己肉眼比对 |
| 无依据时拒答 / 通用知识声明 | `safety.py` `refusal_text()`、SYSTEM_GUARD | 拒答和通用知识回答与正常回答**长得一样**，用户无法一眼区分可信层级 |

**本功能交付两件事：**

1. **回答可信度可视化**：每条 AI 回答给出一个可解释的可信度等级（高/中/低/无依据），等级由可复现的信号算出，附分解明细（不是拍脑袋的百分比）；
2. **引用溯源高亮**：回答里的 `[1][2]` 变成可交互的上标引用，点击/悬停与引用 chip 双向联动、互相高亮，展开片段时**高亮被引用支撑的具体句子**。

## 2. 可信度模型（全部信号已落库，无需新增 AI 调用）

### 2.1 回答模式判定（第一层）

| 模式 | 判定条件 | 展示 |
|---|---|---|
| `refusal` 无依据拒答 | `use_rag && hits 为空 && memories 为空`（chat_service 已有该分支） | 灰色徽章「无笔记依据」 |
| `general` 通用知识 | `use_rag=false` 或无命中但模型声明用通用知识 | 蓝灰徽章「通用知识 · 未引用笔记」 |
| `memory` 记忆作答 | 有 memories 且 hits 为空 | 紫色徽章「基于记忆」 |
| `rag` 笔记作答 | hits 非空 | 正常可信度评分（见 2.2） |

### 2.2 rag 模式可信度评分（0–100，三因子加权）

```
score = 100 × (0.5 × coverage + 0.3 × quality + 0.2 × validity)
```

| 因子 | 含义 | 计算 |
|---|---|---|
| **coverage 依据覆盖度** | 回答中事实性句子被 `[n]` 标注的比例 | 按中英文句号/问号/换行切句，剔除开场白与列表引导句后，`含[n]的句子数 / 总句数`，clamp 到 [0,1] |
| **quality 检索质量** | 被引用片段的语义相关度 | 取**被实际引用**的 hits 的最大 `vector_score`（cosine ∈ [0,1]），线性映射 `(v − 0.30) / (0.75 − 0.30)` 后 clamp；向量降级时（BM25-only）该因子按 0.5 中性值处理并在明细里标注「向量检索不可用」 |
| **validity 引用有效性** | 引用编号是否真实存在 | `answer` 中出现的编号 ⊆ 检索返回的编号集合 → 1.0；出现幻觉编号（如只有 2 个片段却标了 [3]）按比例扣减 |

分级阈值（常量定义在 service 顶部，与 `TREND_DAYS` 风格一致）：

- `score ≥ 70` → **高可信**（绿）
- `45 ≤ score < 70` → **中可信**（黄）
- `score < 45` → **低可信**（橙红）
- 任一因子缺失（如 validity=0 出现幻觉引用）时等级封顶为「中」

> 为什么不用 LLM 打分：MVP 全部因子来自**检索管线自身数据 + 正则切句**，零额外 token 成本、评委可复现验证。LLM 一致性校验放二期（§9）。

### 2.3 明细结构

```json
{
  "mode": "rag",
  "score": 78,
  "level": "high",
  "factors": { "coverage": 0.8, "quality": 0.71, "validity": 1.0 },
  "cited_indices": [1, 2],
  "invalid_indices": [],
  "sentence_count": 10,
  "cited_sentence_count": 8
}
```

## 3. 引用溯源高亮（前端为主，后端零改动）

### 3.1 `[n]` → 可交互上标

- 渲染管线不变（`MarkdownIt(html:false)` + `DOMPurify.sanitize`），在 **sanitize 之后的 HTML** 上做 DOM 后处理：遍历文本节点，把 `[1]` `\[2\]` 等（含 Markdown 转义形态）替换为 `<sup class="rh-cite-ref" data-cite="1">1</sup>`；
- DOMPurify 默认放行 `class` 与 `data-*`，无需改配置；正则只匹配 `[\d+]` 纯数字形态，避免误伤 Markdown 链接语法 `[text](url)`（text 为数字但带 `(` 跟随的不处理）；
- 样式走 `--rh-ai` 色系胶囊小上标，cursor: pointer，焦点可达（button 语义，`aria-label="查看引用来源 1"`）。

### 3.2 双向联动（核心交互）

```
┌─ 点击/悬停回答中的 [1] ──→ 对应引用 chip 高亮 + 自动展开片段
│                            片段内支撑句高亮（见 3.3）
└─ 点击引用 chip ──→ 回答正文中所有 [1] 上标脉冲高亮 2 次
                     （多段引用同一来源时全部点亮）
```

- 悬停 300ms 防抖触发预览高亮，点击才展开片段（沿用现有 `activeCitationId` 单展开逻辑）；
- 联动状态是纯组件内 ref，不进 Pinia store。

### 3.3 片段内支撑句高亮（溯源最后一厘米）

现有 snippet 是 chunk 前 200 字符的纯文本。展开片段时：

1. 取触发该引用的**回答句子**（点击的那个 `[n]` 所在句）；
2. 按句切分 snippet，用字符 bigram 相似度（复用 `retrieval.tokenize` 的中英混合思路，前端实现精简版）选最相似的一句；
3. 相似度 ≥ 0.35 → 该句加 `--rh-ai-subtle` 背景高亮；低于阈值不高亮（诚实呈现「依据是整段」而不是强行标一句）。

> 不做笔记全文定位跳转：chunk → 原文 offset 映射成本高、收益低，一期把「片段内句子级高亮」做扎实即可，跳转放二期。

## 4. SSE 协议增量

沿用现有 `meta / citation / token / done / error` 协议，新增一个事件：

```
event: trust
data: {"mode":"rag","score":78,"level":"high","factors":{...},"cited_indices":[1,2],"invalid_indices":[]}
```

- **时机**：`token` 流结束、`done` 之前发出（评分依赖完整 answer）；
- `done` 事件不变，前端兼容旧后端（收不到 `trust` 就不显示徽章）；
- 无依据拒答分支也会发 `trust`（mode=refusal, score=0），保证每条回答都有等级。

## 5. 后端实现清单

| 文件 | 改动 |
|---|---|
| `app/services/ai/trust.py` | **新文件**：`compute_trust(answer, hits, use_rag, has_memory) -> dict`。纯函数、无 IO，切句、因子计算、分级全在这里；阈值/权重常量置顶 |
| `app/services/ai/chat_service.py` | ① 拒答分支补发 `trust` 事件；② 正常分支在 `done` 前计算并 `yield sse_event("trust", ...)`；③ `_persist` 时把 trust 存入 assistant 消息 |
| `app/models/ai.py` | `AIMessage` 增加可空列 `trust_json: str | None`（旧消息为 NULL，前端不渲染徽章）；Alembic 迁移一条（走 ADR-007 流程） |
| `app/routers/ai.py` | `GET /conversations/{id}/messages` 响应中把 `trust_json` 解析为 `trust` 字段返回（历史消息回看也有徽章） |
| `app/schemas/ai.py` | `MessageOut` 增加 `trust: dict | None = None` |
| `tests/` | 新增 `tests/test_trust.py`：纯函数覆盖（覆盖度切句、幻觉编号扣减、BM25 降级中性值、refusal 分支）、SSE 事件顺序（trust 在 done 之前）、历史消息返回 trust |

伪代码（trust.py 核心）：

```python
COVERAGE_W, QUALITY_W, VALIDITY_W = 0.5, 0.3, 0.2
HIGH, MID = 70, 45

def compute_trust(answer, hits, use_rag, has_memory) -> dict:
    if use_rag and not hits and not has_memory:
        return {"mode": "refusal", "score": 0, "level": "none", ...}
    if use_rag and not hits and has_memory:
        return {"mode": "memory", ...}          # 不评分，只给模式徽章
    if not use_rag or not hits:
        return {"mode": "general", ...}
    cited = extract_indices(answer)             # 正则 \[(\d+)\]
    validity = valid_ratio(cited, len(hits))    # 幻觉编号扣减
    coverage = cited_sentence_ratio(answer)
    quality = quality_from_vectors(cited, hits) # 向量降级→0.5 中性
    score = round(100 * (COVERAGE_W*coverage + QUALITY_W*quality + VALIDITY_W*validity))
    level = "high" if score >= HIGH and validity > 0 else ("mid" if score >= MID else "low")
    return {"mode": "rag", "score": score, "level": level, "factors": {...}, ...}
```

## 7. 安全与成本

1. **零额外 AI 成本**：MVP 评分是纯本地计算，不增加任何 token 消耗与配额压力；
2. **不引入注入面**：`[n]` 解析只认纯数字，模型若输出 `[1](javascript:...)` 之类不会成为链接（DOMPurify 兜底 + html:false）；
3. **诚实呈现**：BM25 降级、片段相似度低于阈值时**明确不标注**，宁可少高亮也不伪造精确溯源——这正是「可信」卖点的反面自证；
4. **旧数据兼容**：`trust_json` 为 NULL 的历史消息只显示引用 chip、不显示徽章，不做读取时重算（回答文本在但检索上下文已不在，重算会失真）。

## 8. 边界与异常

| 场景 | 处理 |
|---|---|
| 回答无任何 `[n]`（rag 模式） | coverage=0 → 低可信，徽章 tooltip 提示「AI 未标注依据，请谨慎采信」 |
| 模型幻觉编号（[5] 但只有 2 段） | validity 按比例扣减，等级封顶「中」，明细里列出无效编号 |
| 流式中断 / provider error | 不发 trust 事件，前端徽章不渲染 |
| snippet 过短（<2 句） | 支撑句高亮直接跳过，整段展示 |
| 通用知识回答里模型手滑标了 [n] | SYSTEM_GUARD 已禁止；若出现，编号不在 hits 中 → validity=0，自动降级为低可信并显示「无效引用」 |
| 深浅主题 | 三级可信度色两套令牌各自校验对比度 ≥ 4.5:1 |

## 9. 二期扩展（不在本期）

- **LLM 一致性校验**：用 fast model 对「回答句子 ↔ 被引片段」做逐条 entailment 校验，把 validity 换成模型判定（评测闭环已有 provider mock 基建，成本可控），作为第四因子参与评分；
- **笔记原文跳转**：chunk 保存起止 offset，点击片段句直接跳笔记编辑器定位；
- **可信度趋势**：接入 ROI 看板（`ai_usage_logs` 场景维度加 trust 均值），观察「可信度随笔记库质量的变化」；
- **低可信自动改进建议**：低可信时提示「去补充相关笔记」或「开启重新索引」。

## 10. 实施顺序（可照做的 checklist）

1. 后端：`trust.py` 纯函数 + pytest → `AIMessage.trust_json` 迁移 → `chat_service` 两处发事件 + 持久化 → messages 接口返回 trust
2. 前端：`theme.css` 新令牌 → `TrustBadge.vue` → `AIMessage.vue` 上标后处理 + 双向联动 + 支撑句高亮 → SSE/store 接线
3. 冒烟：RAG 问答（有引用 / 无命中拒答 / 关闭 RAG / 幻觉编号四种回答各验一次徽章与联动）；历史会话回看；深浅主题 + `npm run build`

验收标准：
- 每条 RAG 回答旁有可解释的可信度徽章，hover 可看三因子分解；拒答与通用知识回答有独立徽章；
- 回答中 `[n]` 为可点击上标，与引用 chip 双向高亮联动，展开片段能看到支撑句高亮；
- `ai_messages.trust_json` 落库，历史消息接口返回 trust，旧消息优雅降级；
- 全程零新增 AI 调用成本；`uv run pytest` 与 `npm run build` 全绿。

## 11. 为什么这是比赛加分项（评审视角）

1. **可解释、可验证**：可信度不是模型自评的玄学分数，而是覆盖率/检索质量/引用有效性三个能当场复算的信号，评委可对着公式验证；
2. **闭环完整**：检索 → 标注 → 评分 → 联动高亮 → 引导用户补笔记，链条最后「一厘米」（片段内句子级溯源）主流产品也少有做到；
3. **零成本差异化**：不增加推理成本就能讲出「可信 AI」故事，演示稳定不易翻车；
4. **诚实即卖点**：向量降级、相似度不足时明确降级展示，把「不伪造溯源」本身设计成产品原则。

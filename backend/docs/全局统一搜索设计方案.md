# 全局统一搜索（Ctrl/Cmd + K）设计方案

> 版本：v1.0（2026-11-05）
> 状态：已实现
> 关联模块：笔记检索（note_service.py）、提示词检索（prompt_service.py）、前端导航（NavBar.vue / App.vue）
> 定位：把散落在「笔记库搜索框 / 提示词库搜索框」两处的局部搜索，升级为**全站一键直达的命令面板**——任何页面按 `Ctrl + K`（macOS 为 `Cmd + K`）即可搜笔记、搜提示词、直达功能页。这是比赛「信息架构效率」演示的关键交互点。

---

## 1. 背景与现状差距

| 已有能力 | 位置 | 缺口 |
|---|---|---|
| 笔记搜索（title/content ilike） | `GET /api/notes?search=` | 只在笔记库页面可用，且要切换页面才能搜 |
| 提示词搜索（title/description/content/tags） | `GET /api/prompts?search=` | 只在提示词库页面可用 |
| 分类树导航 | NoteTree / 分类下拉 | 无统一入口 |
| 无任何全局快捷键 | — | 用户找一条旧笔记需要「回工作台 → 点导航 → 输搜索词」三步 |

**本功能交付三件事：**

1. **统一搜索 API**：一个 `GET /api/search` 端点同时检索笔记 + 提示词，返回带摘要片段（snippet）的聚合结果，一次请求完成跨模块搜索；
2. **命令面板组件**：类 Spotlight / Raycast 的居中浮层，输入即搜、结果分组、键盘可完整操作（↑↓ 选择、Enter 跳转、Esc 关闭）；
3. **全局快捷键 + 常驻入口**：`Ctrl/Cmd + K` 全站唤起；侧边栏增加搜索按钮（显示快捷键徽标）保证可发现性，并内置「快捷操作」兜底项（无结果时直达新建/功能页）。

## 2. 交互设计

### 2.1 唤起与关闭

| 触发方式 | 行为 |
|---|---|
| `Ctrl + K`（Windows/Linux）/ `Cmd + K`（macOS） | 全局唤起/再次按下关闭（toggle） |
| 侧边栏「搜索」按钮 | 唤起（同快捷键） |
| `Esc` | 关闭面板 |
| 点击遮罩层 | 关闭面板 |
| 选中结果 `Enter` | 跳转目标路由并关闭 |

唤起时：面板打开、输入框自动聚焦、清空上一次的关键词（保留会导致「打开就是旧结果」的困惑）。登录页不渲染该组件（无导航栏也无搜索需求）。

### 2.2 结果面板结构

```
┌──────────────────────────────────────┐
│ 🔍 输入关键词搜索笔记与提示词…        │  ← 顶部输入框，占位符含提示
├──────────────────────────────────────┤
│ 笔记                                 │  ← 分组标题（命中数 > 0 才显示）
│  📄 标题【高亮匹配】                  │
│     …正文摘要片段【高亮匹配】… 分类名 · 3 天前
│  📄 …                                │
│ 提示词                               │
│  ✨ 标题【高亮匹配】                  │
│     …正文/简介摘要… 分类名 · 2 周前   │
│ 快捷操作                             │  ← 始终显示，按输入过滤
│  ＋ 新建提示词    📖 打开笔记库 …    │
├──────────────────────────────────────┤
│ ↑↓ 选择  ↵ 跳转  Esc 关闭            │  ← 底部快捷键提示条
└──────────────────────────────────────┘
```

- 空态（无关键词）：只显示「快捷操作」组，用户可以直接当启动器用；
- 无结果态：显示「未找到与 “xxx” 相关的内容」+ 快捷操作组；
- 加载态：请求期间沿用上次结果（不清空、不闪烁），不显示骨架屏——命令面板搜索通常 <300ms，骨架屏反而引入跳动。

### 2.3 键盘导航

| 按键 | 行为 |
|---|---|
| `↑` / `↓` | 在扁平化结果列表中移动高亮项，循环滚动到可视区 |
| `Enter` | 确认当前高亮项 |
| `Esc` | 关闭 |
| 输入框内 `↑↓` | 阻止光标移动到行首行尾的默认行为 |

初始高亮第一项；关键词变化后重置为第一项。

## 3. API 设计

### 3.1 端点

```
GET /api/search?q=<关键词>&limit=<每类条数>
```

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `q` | string | 必填，1–100 字符 | 搜索关键词 |
| `limit` | int | 5（1–10） | **每种类型**返回的最多条数 |

需要 JWT 认证（`get_current_user`），只搜当前用户自己的内容（`visibility` 不参与过滤——广场公开搜索是另一个页面的事，命令面板定位是「找自己的东西」）。

### 3.2 响应结构

```json
{
  "code": 200,
  "msg": "搜索成功",
  "data": {
    "query": "docker",
    "total": 3,
    "items": [
      {
        "type": "note",
        "id": 12,
        "title": "Docker Compose 编排",
        "snippet": "…使用 docker compose up --build 启动完整服务…",
        "category_name": "运维笔记",
        "tags": ["docker", "deploy"],
        "updated_at": "2026-10-30T12:00:00"
      },
      {
        "type": "prompt",
        "id": 7,
        "title": "容器排障助手",
        "snippet": "…你是一名容器运维专家，请分析 {{error_log}}…",
        "category_name": "DevOps",
        "tags": ["运维"],
        "updated_at": "2026-11-01T09:30:00"
      }
    ]
  }
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `type` | `note` / `prompt`，前端据此分组与映射路由 |
| `snippet` | 正文（或简介）中**首个命中位置前后约 80 字符**的摘要片段，换行压成空格，前后加 `…`；标题命中而正文未命中时取正文开头 |
| `category_name` | 批量查询分类名（复用 `CategoryService.get_name_map`，避免 N+1） |
| 排序 | 标题命中优先于正文命中，同级按 `updated_at` 降序；提示词组整体排在笔记组之后（命令面板场景笔记更多） |

### 3.3 路由映射（前端职责）

| type | id → 跳转 |
|---|---|
| `note` | `/notes`（笔记库单页应用，选中项高亮由页面自身承接） |
| `prompt` | `/prompts/{id}` |

## 4. 后端实现

```
backend/app/
├── routers/search.py      # GET /api/search，参数校验 + 聚合两路查询 + 组装响应
└── services/search_service.py  # SearchService：SQL 查询 + snippet 提取 + 排序打分
```

- `SearchService.search_notes(db, user_id, q, limit)` / `search_prompts(...)`：`or_(ilike)` 四路/两路字段匹配，标题命中记 `title_hit=True` 用于排序；
- snippet 提取在 Python 侧完成（SQL 不做文本处理）：`content.lower().find(q.lower())` 定位 → 截取 ±80 字符 → `re.sub(r'\s+', ' ')` 压缩空白；
- 两路查询各自 limit 条，总量很小，单请求无需分页；
- 注册于 `main.py`：`app.include_router(search.router, prefix="/api/search", tags=["全局搜索"])`。

**不做的事（明确划界）：** 不做全文索引/分词（MySQL 5.7 ngram FULLTEXT 与现有 ilike 体系一致即可，数据量个人级）；不做搜索历史（二期可加）；不搜广场内容与 AI 会话。

## 5. 前端实现

```
frontend/src/
├── api/search.ts                      # searchApi.search(q, limit)
├── composables/useGlobalSearch.ts     # 模块级单例 ref：isOpen + open()/close()/toggle()
├── components/search/GlobalSearch.vue # 命令面板（浮层 + 输入 + 分组结果 + 键盘导航）
└── App.vue                            # 非登录页挂载 <GlobalSearch />
```

- **单例 composable**：沿用 `useTheme.ts` 的模块级单例模式，NavBar 按钮与 GlobalSearch 组件通过同一 ref 通信，不引入事件总线；
- **防抖 250ms** + 请求序号守卫（只采纳最后一次请求的结果，防乱序）；
- **关键词高亮**：对 `title`/`snippet` 做大小写不敏感的分段渲染（`<mark class="gs-hl">`），不引入第三方高亮库；
- **快捷操作**（前端静态数据，按输入过滤 label）：

  | label | 跳转 |
  |---|---|
  | 新建提示词 | `/prompts/new` |
  | 打开 AI 工作台 | `/ai` |
  | 打开笔记库 | `/notes` |
  | 打开提示词库 | `/prompts` |
  | 打开 ROI 看板 | `/roi` |
  | 打开资源广场 | `/plaza` |
  | 打开设置 | `/settings` |

- **样式规范**：全部使用 `--rh-*` 令牌（`--rh-z-popover` 层级、`--rh-bg-elevated` 面板底色、`--rh-shadow-lg` 投影、`--rh-radius-md` 圆角、`--rh-transition` 过渡），scoped 样式内不硬编码色值；高亮色用 `--rh-primary-subtle` 背景 + `--rh-primary` 文字；图标按钮带 `aria-label`；禁止 `transition: all`。

### 快捷键监听

- `GlobalSearch.vue` 在 `onMounted` 绑定 `window.keydown`：`event.ctrlKey || event.metaKey` 且 `key === 'k'`（不区分大小写）→ `preventDefault()`（拦截浏览器默认搜索聚焦）→ toggle；
- 输入法组合输入期间（`isComposing`）不响应 Enter 选择，避免中文输入法选词误触跳转。

## 6. 边界情况

| 场景 | 处理 |
|---|---|
| 关键词含 `%` / `_`（ilike 通配符） | 后端原样传给 ilike 会放大匹配范围，MVP 接受（与现有笔记/提示词搜索行为一致，保持全局一致） |
| 请求失败 | 静默保留上次结果 + 顶部浅色错误行提示「搜索失败，请稍后再试」（复用 `getApiErrorMessage`） |
| 登出后再按 Ctrl+K | 组件仅挂在非登录页，登出跳转后自然不可用 |
| 移动端 | 侧边栏搜索按钮在 768px 以下隐藏（跟随 `.workspace-nav` 隐藏），移动端仍可用页面内搜索 |
| 与浏览器冲突 | preventDefault 拦截 Chrome 的「搜索选中内容」默认行为 |
